# 产品定位

## 设计锚点

本文件遵循七层模型和 `VNextLanguageContract`。任何写入必须进入办理项/WorkItem 和提交确认；产品定位不得替代事实归属或当前 OAM 权威。

## 一句话定位

Work OS vNext 是移动端优先、三语言可用的公司经营执行系统，把来源、主体、车辆、业务域、财务、办理项、摘要和管理分析统一到一套可追踪、可协作、边界清楚的经营操作系统里。

## 目标用户

- 一线经办人：接需求、查对象、办任务、补证据、提交确认。
- 财务人员：承接金额依据，确认收款、付款、押金、费用、工资、报销、核销和核算。
- 主管/经理：处理阻断、超时、转交、验收、升级和拍板前置判断。
- 管理层：看经营摘要、风险、趋势、异常和少量拍板入口。
- 治理/审计岗：查来源、主体、关系、证据、权限、操作轨迹和修正链。
- 三语言用户：中文、俄语、吉语用户在同一业务合同下办理，不因语言不同改变事实归属。

## 核心价值

- 少找入口：用户从今日、工作项、搜索、我的进入，不从应用树开始。
- 少重复录入：来源、主体、车辆、关系和上游事实只在权威位置形成，下游只读复用。
- 少混事实：来源、业务事实、财务事实、管理摘要、分析结果互不替代。
- 少断链：来源、主体解析、业务接入、办理项、财务承接、摘要、审计串成闭环。
- 少越界：每个域知道自己拥有什么、能读什么、不能写什么。
- 少语言错位：展示 label 本地化，提交 value 稳定中立，三语言体验不改变业务含义。

## 非目标

- 不是宿舍系统：宿舍只是第一条样板切片。
- 不是 CRM/ERP/HR/财务软件拼盘：这些能力被吸收进统一经营结构。
- 不是应用商店：应用职责群只是能力目录、权限和筛选，不是一级入口。
- 不是报表系统：报表和分析只读观察，不替代业务办理。
- 不是翻译表：三语言是体验合同和验收边界，不是页面临时文案。
- 不是当前 OAM 的替代文件：落地前必须映射和评审。

## 设计原则

1. 来源归因全域通用，业务域只在接入确认后形成自己的事实。
2. 共享治理只管主对象、关系、去重和共享状态，不吞业务事实。
3. 业务域拥有业务事实，合同与财务域拥有正式财务事实。
4. 办理项/WorkItem 是唯一可写执行入口。
5. 读模型与分析层只读消费摘要，不处理异常，不写事实。
6. 移动端按人和任务收口，页面按主对象和办理项推进。
7. 已确认事实只能追加修正，不能原地编辑。
8. 用户可见语言必须覆盖中文、俄语、吉语；稳定值不得直接展示。

## 用户语言

普通用户界面使用：

- 办理项、待办、任务
- 来源、申请、需求、承接来源
- 主体、车辆、关系
- 提交确认
- 当前不可处理原因
- 摘要、经营摘要、分析
- 只读、待补证据、等待财务、下一步

普通用户界面不显示：

- WorkItem、OperationCase、Confirm Runtime、Unit of Work
- Projection、Lens、payload hash、definitionId、raw code
- 内部 ID 作为主标题
- enum/status/action 的稳定 value
