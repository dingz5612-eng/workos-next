# 执行与跨域移交

## 设计锚点

本文件遵循七层模型和 `VNextLanguageContract`。执行层只提供唯一写入路径；事实归属仍回到对应权威层。

## VNextExecutionItem

`VNextExecutionItem` 是用户可见的办理项，架构映射 WorkItem。它是唯一可写执行入口。

办理项合同：

| 字段 | 作用 |
| --- | --- |
| `primaryBusinessObject` | 当前办理对象，如来源接入、住宿申请、维修单、财务承接单、管理拍板记录。 |
| `responsibleRole` | 当前责任角色和可办理范围。 |
| `requiredReadContext` | 页面必须展示的只读上下文，来自来源、主对象、上游事实、财务摘要或读模型。 |
| `editableInputs` | 用户本次真正需要填写的输入。 |
| `fixedSelections` | 只能从权威选项选择的字段，不得退化为手填。 |
| `evidenceRequirements` | 必需或可选证据、当前状态和缺失原因。 |
| `financialContext` | 金额、币种、业务对象、收付方向、阶段语义、应收/已收/本次/差额。 |
| `legalActions` | 页面按钮、流程动作和状态机动作，不得进入表单字段。 |
| `blockingReasons` | 当前不可处理原因、补救责任域和下一步。 |
| `handoffSummary` | 上一步带入什么、提交后承接到哪里。 |
| `searchReadModel` | 提交后输出或更新的只读摘要范围。 |
| `displayKeys` | 标题、说明、按钮、字段、状态、错误的三语言 key。 |
| `auditRef` | 来源、责任人、证据、提交确认和结果的审计引用。 |

## 执行流

```text
来源、主对象或只读摘要
-> 上下文读取
-> 合法动作选择
-> 办理项创建或打开
-> 准备/校验
-> 证据绑定
-> 提交确认
-> 形成归属层事实
-> BusinessSummaryReadModel 和回执更新
-> 下一办理项、等待回执、阻断或只读记录
-> 审计追踪
```

## 来源到业务接入

```text
SourceAttribution
-> SubjectResolution
-> DomainIntake
-> VNextExecutionItem
```

规则：

- 来源有效但主体未解析时，不能进入业务域事实。
- 主体已解析但业务域未确认时，只能停留在待转域。
- `DomainIntake` 是业务域接入对象，不是来源对象。
- 业务域确认后，后续状态归业务域所有。
- 接入失败必须返回可读失败路由，不能只显示技术错误。

## 跨域移交

允许移交：

- 来源转业务域接入。
- 业务域转财务承接。
- 业务域转共享治理解析。
- 业务域转其它业务域协作。
- 管理拍板回业务域或财务域。

移交必须包含：

- 来源对象或业务对象。
- 移交原因。
- 上游只读摘要。
- 当前证据状态。
- 当前不可处理原因。
- 目标责任域。
- 下一办理项。
- 三语言用户提示。

禁止移交：

- 源域事实所有权。
- 正式财务事实副本。
- 已确认事实可编辑副本。
- 技术字段作为用户文案。

## 财务承接

业务域只能输出：

- 金额依据
- 费用依据
- 押金申请
- 退款/扣减依据
- 工资/报销依据
- 来源业务对象

合同与财务域形成：

- 收款事实
- 付款事实
- 押金财务事实
- 费用财务事实
- 工资支付事实
- 报销支付事实
- 核销和核算事实

财务承接结果以摘要和回执返回业务域，不把财务事实复制给业务域。

## ManagementDecisionRecord

`ManagementDecisionRecord` 是管理拍板记录，只能记录拍板和路由，不直接处理异常。

字段：

- `decisionObject`：被观察的经营摘要、风险或异常。
- `decisionContext`：只读依据、时间范围、来源域和审计引用。
- `decisionText`：管理意见。
- `decisionOwner`：拍板人和角色。
- `targetDomain`：后续责任域。
- `requiredExecutionItem`：必须创建或打开的后续办理项。
- `forbiddenEffects`：不得关闭异常、不得写财务真值、不得改业务事件。
- `displayKeys`：三语言标题、按钮、状态和错误。
- `auditRef`：拍板链路。

拍板后只能进入：

- 业务域办理项。
- 财务承接办理项。
- 共享治理复核办理项。
- 已完成只读记录。

## 完成态

办理项提交后只允许进入：

- 下一办理项
- 等待回执
- 已完成只读记录
- 投影同步中
- 被阻断
- 追加修正

不得通过原页面重复提交或原地编辑修改已确认事实。

## 追加修正

已确认事实出现错误时：

```text
只读记录
-> 发起修正
-> 修正办理项
-> 提交确认
-> 修正事件
-> 摘要更新
-> 审计链保留原事实和修正事实
```

修正不得覆盖原事实，必须形成可追踪链。

## 审计

审计追踪必须能回答：

- 来源从哪里来。
- 主体和车辆如何解析。
- 谁在什么角色下创建办理项。
- 系统带出了什么。
- 用户填写了什么。
- 绑定了什么证据。
- 提交确认形成了什么事实。
- 摘要回写给了谁。
- 是否发生过追加修正。
- 用户当时使用的语言、展示 key 和提交 value 是否分离。
