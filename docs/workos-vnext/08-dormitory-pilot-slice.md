# 宿舍样板切片

## 设计锚点

本文件遵循七层模型和 `VNextLanguageContract`。宿舍只验证通用模型；任何住宿写入必须进入办理项/WorkItem 和提交确认。

## 样板定位

宿舍只用于验证 Work OS vNext 总模型，不反向主导总设计。

宿舍样板验证：

- 来源归因。
- 主体解析。
- `DomainIntake`。
- 房间床位资源。
- 费用依据和押金申请。
- 财务承接。
- 入住、续住、换房、退住。
- `BusinessSummaryReadModel` 摘要回写和管理只读分析。
- 中文、俄语、吉语三语言可办理。

## 外部住宿客户

```text
SourceAttribution：广告、推荐、电话、企业联系人
-> SubjectResolution：识别外部主体和关系
-> DomainIntake：dormitory.external_stay_intake
-> VNextExecutionItem：住宿申请办理项
-> 住宿单
-> 房间床位选择
-> 费用依据和押金申请
-> 财务承接
-> 入住确认
```

边界：

- 来源不是住宿事实。
- 主体由共享治理解析。
- 住宿单归销售与宿舍经营域。
- 押金财务事实归合同与财务域。

三语言体验：

- 来源、住宿需求、房间、床位、押金申请、等待财务、入住确认必须三语言可读。

## 内部员工住宿

```text
SourceAttribution：内部申请或管理指派
-> SubjectResolution：内部主体和员工关系
-> DomainIntake：dormitory.employee_stay_intake
-> VNextExecutionItem：住宿申请办理项
-> 住宿单
-> 房间床位选择
-> 费用依据或内部结算依据
-> 财务承接或内部回执
-> 入住确认
-> 人事行政只读员工住宿摘要
```

边界：

- 人事行政拥有员工关系，不处理住宿服务动作。
- 宿舍域拥有住宿事件和房间床位状态。
- 财务域拥有正式支付或结算事实。

## 押金承接

```text
住宿单
-> 押金申请
-> 财务承接办理项
-> 押金财务事实
-> 财务结果摘要
-> 宿舍只读消费回执
```

边界：

- 押金申请不是押金财务事实。
- 宿舍不能确认正式收款。
- 共享治理只读消费状态回执。
- 页面必须显示金额、币种、业务对象、收付方向和阶段语义。

## 退住结算

```text
退住办理项
-> 房间床位检查
-> 退住费用/扣减/退款依据
-> 财务承接结算
-> 财务结果摘要
-> 关闭住宿单
-> 床位恢复可经营或进入清洁/维修
```

边界：

- 房间床位检查未完成不得释放资源。
- 页面金额不能直接成为财务事实。
- 清洁或维修未完成，床位不得恢复可经营。
- 关闭后只能追加修正。

## 可复制模式

| 宿舍元素 | 通用模式 | 可复制业务域 |
| --- | --- | --- |
| 住宿来源 | `SourceAttribution` | 维修、配件、人事、车辆服务 |
| 住客主体 | `SubjectResolution` | 所有涉及人/组织/车辆的域 |
| 住宿申请 | `DomainIntake` | 维修接待、配件需求、行政申请 |
| 住宿单 | 业务执行对象 | 维修单、运行任务、人事服务单 |
| 房间床位 | 资源占用状态 | 车辆、设备、库存、工位 |
| 费用依据 | 业务金额依据 | 维修报价、配件销售、报销依据 |
| 财务承接 | 财务真值入口 | 所有产生收付的域 |
| 退住结算 | 生命周期关闭 | 维修交付、车辆退场、人员离职 |
| 三语言办理 | `VNextLanguageContract` | 全业务域移动端 |
