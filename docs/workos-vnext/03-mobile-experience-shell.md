# 移动端体验壳

## 设计锚点

本文件遵循七层模型和 `VNextLanguageContract`。移动端体验只组织阅读、选择、确认和路由；任何写入必须进入办理项/WorkItem 和提交确认。

## 一级入口

移动端一级入口固定为：

1. 今日
2. 工作项
3. 搜索
4. 我的

应用职责群、业务域、来源渠道、管理看板都不得成为一级入口。

## 主操作流

移动端所有主动办理都必须落到以下路径之一：

```text
今日或搜索
-> 来源卡
-> 主体解析卡
-> 转域确认卡
-> 办理项
-> 提交确认
-> 财务承接、下一办理项、等待回执或已完成只读记录
```

```text
今日或工作项
-> 已分派办理项
-> 读取上游只读摘要
-> 填写当前输入或固定选择
-> 绑定证据
-> 提交确认
-> 下一步承接
```

```text
搜索或驾驶舱
-> BusinessSummaryReadModel 只读摘要
-> 合法动作判断
-> 办理项或 ManagementDecisionRecord
-> 回业务域或财务域继续办理
```

页面不得在来源卡、搜索结果、分析卡、对象摘要或我的页面中直接写业务事实。

## 今日

回答：“我现在最该处理什么？”

显示优先级：

1. 阻断和超时。
2. 可立即处理的办理项。
3. 需要补证据的办理项。
4. 等待上游、财务、主管或治理的事项。
5. 来源待接入、主体待解析、重复待确认。
6. 已提交但摘要同步中的事项。
7. 学习、权限和支持提示。

今日不得直接写事实，不得用报表摘要代替办理项，不得把应用目录放在任务之前。

## 工作项

回答：“我负责的事有哪些，下一步是什么？”

工作项分组：

- 可立即处理
- 来源待接入
- 主体待解析
- 等待证据
- 等待上游
- 等待财务
- 等待主管
- 已阻断
- 已提交同步中
- 已完成可查看

每个工作项必须显示：

- 主对象或来源
- 当前动作
- 系统已带出的上下文
- 用户本次要填或选择什么
- 证据状态
- 财务边界
- 当前不可处理原因
- 提交后下一步

## 搜索

回答：“我知道一个人、车、来源、业务对象或财务对象，能去哪里？”

搜索结果分为：

- 来源记录
- 主体
- 车辆
- 关系
- 业务接入对象
- 业务执行对象
- 财务对象
- 已完成记录
- 审计追踪

搜索结果默认只读。只有合法动作满足角色、对象状态、设备、证据和业务条件时，才显示办理入口。搜索结果必须消费 `BusinessSummaryReadModel`，不得直接读取源域内部字段作为用户主信息。

## 我的

回答：“我是谁、我能做什么、出了问题去哪看？”

内容：

- 当前账号、角色、部门、职责群
- 权限范围和当前不可处理原因
- 当前语言和可切换语言：中文、俄语、吉语
- 设备可信状态
- 草稿、提交队列、离线队列
- 最近办理、最近来源、最近搜索、最近证据
- 学习中心、反馈和支持

我的不得成为业务事实写入口。

## 角色路径

### 一线经办人

```text
今日
-> 可处理办理项或来源待接入
-> 读取来源/对象/上游摘要
-> 填写当前输入或选择固定选项
-> 绑定证据
-> 提交确认
-> 查看下一步承接
```

三语言要求：标题、主按钮、阻断原因、证据名称和下一步提示必须覆盖中文、俄语、吉语。

### 财务人员

```text
工作项
-> 等待财务
-> 读取来源业务对象和金额依据
-> 确认财务事实
-> 输出财务结果摘要
-> 回写业务域或共享治理状态
```

三语言要求：金额、币种、收付方向、押金、退款、核销、核算和错误提示必须三语言可读。

### 主管/经理

```text
今日
-> 阻断、超时、重复、转交
-> 查看责任域、证据和当前不可处理原因
-> 转交、升级、拍板前置判断
-> 回到对应办理项
```

三语言要求：不可处理原因必须说明缺什么、谁处理、处理后去哪，不得只显示技术错误。

### 管理层

```text
今日或搜索
-> 查看只读经营摘要、报警和趋势
-> 形成 ManagementDecisionRecord
-> 路由回业务域或财务域
```

三语言要求：报警、趋势和拍板入口必须明确“只读观察”和“回责任域办理”的区别。

### 治理/审计岗

```text
我的或搜索
-> 查来源、主体、关系、办理项、证据、审计链
-> 处理主对象合并建议或权限问题
-> 发起追加修正办理项
```

三语言要求：合并建议、不可合并原因、审计轨迹和修正说明必须三语言可读。

## 页面体验合同

每个关键页面必须按以下顺序组织：

1. 我在办什么：来源、主对象、办理项和动作。
2. 系统已带出什么：来源摘要、主体解析、上游事实、财务摘要。
3. 我要填什么：当前真实输入或固定选择。
4. 缺什么：证据、权限、上游、财务或设备信任。
5. 影响什么：业务状态、财务边界、风险和下一责任人。
6. 提交后去哪：下一办理项、回执、阻断、只读记录或修正链。

每个页面还必须声明：

- `displayKey`：标题和说明的三语言 key。
- `primaryActionKey`：主按钮三语言 key。
- `statusKey`：状态三语言 key。
- `errorKey`：错误或阻断原因三语言 key。
- `longTextPolicy`：长文案可换行、可缩短、不可遮挡关键操作。
