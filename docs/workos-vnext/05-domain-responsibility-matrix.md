# 业务域职责矩阵

## 设计锚点

本文件遵循七层模型和 `VNextLanguageContract`。业务域只拥有本域事实；任何写入必须进入办理项/WorkItem 和提交确认。

## 设计口径

每个业务域必须声明：

- 可接收来源
- `DomainIntake` 类型
- 接入条件
- 拥有事实
- 输出 `BusinessSummaryReadModel`
- 只读消费
- 禁止越界
- 失败路由
- 三语言责任

## 共享治理

可接收来源：

- 主体接入请求
- 车辆接入请求
- 关系修正请求
- 重复主体/车辆处理请求

`DomainIntake` 类型：

- `governance.subject_resolution_intake`
- `governance.vehicle_resolution_intake`
- `governance.relationship_correction_intake`

拥有事实：

- 主体主对象
- 车辆主对象
- 正式关系
- 主体/车辆画像
- 共享状态、风险回执、阻断回执

输出 `BusinessSummaryReadModel`：

- 主体摘要
- 车辆摘要
- 关系摘要
- 重复和合并建议摘要
- 风险状态摘要

只读消费：

- 来源归因
- 业务域摘要
- 财务结果摘要
- 审计追踪

禁止越界：

- 不拥有业务域源事件。
- 不汇总替代业务域事实。
- 不做经营统计定真。
- 不形成正式财务真值。

失败路由：

- 身份冲突：进入主体解析办理项。
- 重复候选不确定：进入合并建议办理项。
- 关系证据不足：等待证据。

三语言责任：

- 主体类型、重复原因、不可合并原因、风险状态必须三语言可读。

## 合同与财务

可接收来源：

- 业务域金额依据。
- 合同草案。
- 财务承接请求。
- 管理拍板后的财务处理请求。

`DomainIntake` 类型：

- `finance.contract_intake`
- `finance.receipt_intake`
- `finance.payment_intake`
- `finance.deposit_intake`
- `finance.settlement_intake`

拥有事实：

- 合同承接对象
- 收款、付款、押金、费用、工资、报销、退款、扣减
- 核销、核算
- 财务结果摘要

输出 `BusinessSummaryReadModel`：

- 财务承接状态
- 财务确认结果
- 核销和核算状态
- 财务阻断原因

只读消费：

- 主体和关系摘要。
- 业务域金额依据。
- 来源归因。

禁止越界：

- 不拥有业务域源事件。
- 不关闭业务异常。
- 不改主体、车辆或业务对象。

失败路由：

- 金额依据缺币种或业务对象：退回来源业务域。
- 财务证据不足：等待证据。
- 重复收付风险：进入财务复核办理项。

三语言责任：

- 金额、币种、收付方向、押金、退款、核销、核算、支付方式必须三语言可读。

## 销售与宿舍经营

可接收来源：

- 外部住宿线索。
- 企业员工住宿需求。
- 合作方住宿需求。
- 管理指派的住宿处理。

`DomainIntake` 类型：

- `dormitory.external_stay_intake`
- `dormitory.employee_stay_intake`
- `dormitory.corporate_stay_intake`
- `dormitory.checkout_intake`

拥有事实：

- 住宿申请
- 住宿单
- 房间和床位经营状态
- 入住、换房、续住、退住事件
- 住宿费用依据
- 宿舍押金申请
- 宿舍经营摘要

输出 `BusinessSummaryReadModel`：

- 住宿状态
- 房间床位占用状态
- 费用依据摘要
- 押金申请摘要
- 入住/退住风险

只读消费：

- 来源归因
- 主体和关系摘要
- 员工关系摘要
- 财务结果摘要
- 维修/清洁摘要

禁止越界：

- 不拥有入口来源本身。
- 不拥有主体主档。
- 不形成正式收款或押金财务事实。
- 不让人事行政处理住宿服务动作。

失败路由：

- 主体未解析：回共享治理。
- 床位不可用：进入资源处理办理项。
- 财务未承接：等待财务。
- 退住后异常：追加修正办理项。

三语言责任：

- 房间、床位、入住、续住、退住、押金申请、费用依据和清洁/维修状态必须三语言可读。

## 运力与车辆保障

可接收来源：

- 车辆运行需求。
- 司机协作请求。
- 补能保障请求。
- 维修恢复后的经营可用确认。

`DomainIntake` 类型：

- `mobility.vehicle_operation_intake`
- `mobility.driver_collaboration_intake`
- `mobility.energy_support_intake`
- `mobility.availability_confirmation_intake`

拥有事实：

- 车辆运行事件
- 资源日经营
- 司机作业角色关系
- 司机协作事件
- 补能保障事件
- 经营可用状态

输出 `BusinessSummaryReadModel`：

- 运行状态
- 资源日摘要
- 司机协作状态
- 补能状态
- 经营可用回执

只读消费：

- 车辆主对象。
- 主体关系摘要。
- 维修恢复摘要。
- 财务结果摘要。

禁止越界：

- 不拥有车辆主档。
- 不拥有维修施工事实。
- 不形成正式财务真值。

失败路由：

- 车辆关系冲突：回共享治理。
- 维修未恢复：回维修域。
- 补能证据缺失：等待证据。

三语言责任：

- 车辆状态、司机协作、补能、经营可用和阻断原因必须三语言可读。

## 维修与配件服务

可接收来源：

- 客户维修需求。
- 车辆故障来源。
- 配件采购或销售需求。
- 运力域发起的维修协作。

`DomainIntake` 类型：

- `repair.customer_repair_intake`
- `repair.vehicle_fault_intake`
- `parts.fulfillment_intake`
- `repair.internal_support_intake`

拥有事实：

- 维修接待、诊断、施工、质检、交付事件
- 自有车辆恢复事实
- 配件技术支持事件
- 配件采购或销售履约动作
- 库存变化和协作摘要
- 维修/配件费用依据

输出 `BusinessSummaryReadModel`：

- 维修进度
- 质检和交付结果
- 配件履约状态
- 库存变化摘要
- 费用依据摘要

只读消费：

- 来源归因。
- 主体和车辆摘要。
- 运力可用状态。
- 财务结果摘要。

禁止越界：

- 不拥有车辆主档。
- 不确认运力经营可用状态。
- 不形成正式收付和核算事实。

失败路由：

- 车辆未解析：回共享治理。
- 费用依据不完整：回维修办理项。
- 财务承接失败：等待财务。

三语言责任：

- 诊断、施工、质检、交付、配件履约、库存变化、费用依据必须三语言可读。

## 人事行政

可接收来源：

- 内部人员关系请求。
- 培训、证照、考核、评级请求。
- 工资、报销、行政服务请求。
- 员工住宿关系摘要请求。

`DomainIntake` 类型：

- `hr.employee_relation_intake`
- `hr.training_certificate_intake`
- `hr.payroll_basis_intake`
- `admin.service_intake`

拥有事实：

- 内部人员关系
- 培训、证照、考核、评级
- 工资依据、报销依据、行政费用依据
- 内部资产和行政服务事件
- 人员绩效摘要

输出 `BusinessSummaryReadModel`：

- 员工关系摘要
- 培训证照摘要
- 考核评级摘要
- 工资/报销依据摘要
- 行政服务状态

只读消费：

- 主体摘要。
- 员工住宿摘要。
- 财务支付摘要。

禁止越界：

- 不处理住宿服务动作。
- 不形成工资支付或报销支付事实。
- 不把人事关系当作住宿事实。

失败路由：

- 主体未解析：回共享治理。
- 证据不足：等待证据。
- 支付未完成：等待财务。

三语言责任：

- 员工关系、证照、评级、工资依据、报销依据和行政服务状态必须三语言可读。

## 管理驾驶舱与分析

可接收来源：

- 各域 `BusinessSummaryReadModel`。
- 财务结果摘要。
- 风险回执。
- 审计追踪。

`DomainIntake` 类型：

- 不作为普通业务域接入。
- 管理拍板必须形成 `ManagementDecisionRecord`，再路由到责任域办理项。

拥有事实：

- 管理视图配置。
- `ManagementDecisionRecord`。

只读分析产物：

- 报警提示。
- 趋势、排行、转化和效率分析。
- 决策依据快照。
- 风险总览。

输出 `BusinessSummaryReadModel`：

- 经营总览
- 风险总览
- 拍板结果路由摘要

只读消费：

- 所有业务域摘要。
- 财务结果摘要。
- 共享治理状态。

禁止越界：

- 不处理业务异常。
- 不写业务域事件。
- 不写财务真值。
- 不改主体、车辆或关系。

失败路由：

- 需要处理异常：生成对应业务域或财务域办理项。
- 需要拍板：形成 `ManagementDecisionRecord` 后路由。

三语言责任：

- 驾驶舱必须明确区分“只读分析”“拍板记录”“回责任域办理”，三语言都不得暗示管理页面可直接处理异常。
