# vNext 基线与原型策略

## 文件定位

本文件定义 Work OS vNext 的文档基线、原型资产边界和后续高保真重做策略。它只约束 `docs/workos-vnext/` 设计包，不改变当前 OAM Source Authority、generated、runtime、surface、tests、Evidence Root 或发布结论。

## 本次基线范围

本次 vNext 干净基线只包含：

- `docs/workos-vnext/` 总设计包。
- `docs/workos-vnext/dormitory-domain/` 宿舍经营域设计包。

本次 vNext 干净基线不包含：

- `outputs/workos-vnext/`。
- 当前本地宿舍 UI 原型。
- 当前运行中的 WorkOSNext mobile surface。
- 任何 current OAM、generated、runtime、surface、tests 或 CI 修改。

## 当前原型状态

当前 `outputs/workos-vnext/dormitory-ui-prototype/` 的状态是 `rejected local draft`。

它不得作为：

- vNext 高保真 UI 方向。
- baseline、demo、验收件或设计参考。
- 当前 OAM surface 的替代方案。
- 后续原型的视觉继承来源。

它只能作为反例，用来提醒后续设计避免：旧项目观感、普通表单后台、字段厚度不足、对象薄、搜索弱、财务边界不醒目、卡片堆叠和低端 SaaS 模板感。

## 后续高保真方向

后续宿舍高保真 UI 必须按 **Executive Quiet Operations** 融合方向重新制作：

- 高端企业级移动经营系统。
- 象牙白、石墨黑、雾灰、香槟金、钛银、少量深墨蓝。
- 风险、阻断和异常使用酒红或铜色。
- 禁止绿色、青绿色、薄荷绿用于任何状态、按钮、标签、图标或图表。
- 默认中文单语言展示，不做多语言同屏；俄语、吉语能力只作为语言切换和布局压力规则存在。
- 命令搜索是核心能力，不是普通搜索框。
- 字段更厚，但用户少填；更多信息来自只读上下文、对象摘要、财务边界、证据状态、阻断原因和下一步承接。

## 原型重做范围

第一版新原型只做两个完整且可衔接场景：

1. 外部住宿客户入住闭环：今日经营工作台 -> 命令搜索/来源接入 -> 主体确认 -> 房间床位选择 -> 押金/收款财务承接 -> 入住确认 -> 在住摘要。
2. 退住结算到床位恢复再经营闭环：今日经营工作台 -> 命令搜索 -> 退住检查 -> 结算依据 -> 财务回执 -> 床位恢复 -> 资源回流到房间床位选择。

必须重新设计的关键页面：

- 今日经营工作台。
- 命令搜索与推荐办理项。
- 来源接入与主体确认。
- 房间床位选择。
- 押金/收款财务承接。
- 入住确认。
- 退住检查。
- 结算依据。
- 财务回执。
- 床位恢复与资源回流。

## 命令搜索准入

命令搜索必须遵循只读发现和合法动作跳转原则：

- 搜索不写事实。
- 搜索只识别对象、意图、当前状态和推荐办理项。
- 搜索结果必须展示业务对象、状态、关键金额、证据缺口和下一步。
- 用户确认进入办理项后，才允许通过 WorkItem/办理项提交写入。

最低命令样例：

- `0906-1退房`：识别床位、住宿单、住客、押金余额、当前状态，推荐进入退住检查。
- `0906-1退住`：同退房意图。
- `0906-1结算`：推荐进入结算依据。
- `0906-1恢复`：推荐进入床位恢复或资源回流。
- `欧亚物流入住`：推荐进入外部客户入住闭环。
- `欧亚物流押金`：推荐进入押金/收款财务承接。

## 提交策略

vNext 文档基线可以提交和推远端。原型资产只有在重新制作并通过人工设计验收后，才允许单独评审是否提交。

允许提交：

- vNext 架构与领域设计文档。
- 对当前原型的拒绝状态说明。
- 后续高保真重做的设计约束和验收门槛。

禁止提交：

- 当前 rejected 原型目录。
- 从旧 WorkOSNext mobile surface 继承来的视觉结构。
- 为了让原型看起来完整而新增的合同外字段。
- 任何会被误解为 current OAM GO、试运行或发布结论的内容。

## 验收门槛

新的高保真原型进入可提交评审前，必须满足：

- 不像旧后台、普通表单、旧 mobile surface 或低端 SaaS 模板。
- 不显示内部 ID 作为主信息。
- 不把对象选择退化成手填。
- 不把流程动作放进表单字段。
- 每屏回答“我在办什么、系统带出什么、我要填什么、缺什么或为什么阻断、提交后去哪”。
- 宿舍金额依据和财务正式事实边界清楚。
- B 场景恢复后的床位能回流到 A 场景房间床位选择和命令搜索。
- 不修改 current OAM、generated、runtime、surface、tests 或 CI。
