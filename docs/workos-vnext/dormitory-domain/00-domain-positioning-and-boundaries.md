# 宿舍经营域定位与边界

## 设计锚点

本文件属于 Work OS vNext 宿舍经营域设计包，遵循总设计七层模型和 `VNextLanguageContract`。本目录只定义 vNext 领域目标，不修改当前宿舍 13 场景 Source Authority、generated、runtime、surface 或测试。

本域唯一入口和冲突裁决见 `README.md`。状态动作以 `08-state-action-transition-contract.md` 为准，场景步骤字段以 `09-scenario-step-field-contracts.md` 为准；本文件负责定位和边界，不单独裁决执行字段。

## 领域定位

宿舍经营域负责长租公寓式企业员工宿舍和外部住宿客户的住宿经营闭环。它不是单独宿舍软件，而是 Work OS 中“从住宿需求到房间床位经营、入住履约、费用依据、退住结算和摘要回写”的业务域。

目标市场背景为吉尔吉斯斯坦比什凯克，移动端优先，支持中文、俄语、吉语三语言办理。

## 宿舍域拥有

- 住宿申请。
- 住宿单。
- 房间和床位经营状态。
- 房间床位分配、锁定、入住、续住、换房、退住事件。
- 住宿价格快照、费用依据、押金申请、扣减/退款依据。
- 房务检查、清洁、维修协同状态和恢复可经营建议。
- 宿舍经营 `BusinessSummaryReadModel`。

## 宿舍域不拥有

| 不拥有对象 | 归属 |
| --- | --- |
| 来源归因、渠道、触点、原始诉求 | 来源归因层 |
| 主体主档、车辆主档、重复合并、正式关系 | 共享治理层 |
| 员工关系、岗位、考勤、工资依据 | 人事行政域 |
| 正式收款、付款、押金、退款、核销、核算 | 合同与财务域 |
| 维修施工事实、配件履约事实 | 维修与配件服务域 |
| 管理趋势、报警、拍板入口 | 读模型与分析层 |

## 宿舍域与相邻域

| 相邻域 | 宿舍可读 | 宿舍可发起 | 宿舍禁止 |
| --- | --- | --- | --- |
| 来源归因 | 来源摘要、初始证据、候选业务域 | 住宿接入确认 | 改来源、删除来源、把来源当住宿事实 |
| 共享治理 | 主体、组织、员工、关系、重复风险 | 主体解析、关系修正 | 创建正式财务事实、合并业务事件 |
| 人事行政 | 员工关系、住宿资格摘要 | 员工住宿接入、员工住宿摘要回写 | 让人事处理住宿服务动作 |
| 合同与财务 | 财务承接状态、收付回执、押金余额摘要 | 押金申请、收款依据、退款/扣减依据 | 确认正式收款、退款、核销、核算 |
| 维修与配件 | 房务维修状态、恢复建议 | 房间床位维修协同、停售建议 | 确认维修施工事实、配件库存事实 |
| 管理驾驶舱 | 经营摘要被读取 | 只读分析或拍板后回宿舍办理项 | 让驾驶舱直接关闭住宿异常 |

## 唯一执行口

宿舍域所有写动作必须进入 `VNextExecutionItem`/WorkItem 和提交确认。

```text
SourceAttribution
-> SubjectResolution
-> DomainIntake
-> VNextExecutionItem
-> 宿舍业务事实或金额依据
-> BusinessSummaryReadModel
-> 财务承接、下一办理项或只读记录
```

禁止从搜索、房态看板、管理驾驶舱、人员详情、财务摘要或房间床位详情直接写住宿事实。

`DormitoryStateActionTransition` 负责裁决某状态下能不能做某动作；`DormitoryScenarioStepFieldContract` 负责裁决页面展示什么、填什么、选择什么、缺什么、提交后去哪。任何未进入这两个合同的写动作，默认不得作为 vNext 宿舍域正式办理动作。

## 三语言原则

- 页面标题、主按钮、状态、错误、证据名称、金额说明、下一步提示必须覆盖 `zh-CN`、`ru-RU`、`ky-KG`。
- enum、status、action、reason、currency、paymentMethod 使用稳定 value，不直接展示。
- 俄语和吉语长文案不得遮挡金额、证据状态、主按钮和下一步承接区。

## 当前 OAM 边界

当前宿舍 13 场景权威继续有效。vNext 宿舍经营域设计只能作为目标蓝图、映射和差异，不得直接加入 `current-authority-index`，不得改 generated、runtime、surface、tests，不产生当前 OAM GO、可发布、可试运行或用户可亲测结论。
