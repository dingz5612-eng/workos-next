# 宿舍少填与自动带出策略

## 设计锚点

本文件定义 `DormitoryMinimalInputPolicy`。目标是让宿舍移动端办理项尽量少填、少打字、少重复确认，同时保持事实边界清楚。它约束 `09-scenario-step-field-contracts.md` 的 `editableInputs`，并给 `13-screen-field-blueprint.md` 提供页面输入准入。

本文件只约束 vNext 设计包，不修改当前 OAM、generated、runtime、surface 或 tests。

## 字段来源分级

| sourceType | 处理方式 | 示例 |
| --- | --- | --- |
| `systemDerived` | 系统推导，默认只读，不进入输入区 | 来源摘要、主体候选、财务回执、证据状态、审计引用 |
| `upstreamReadOnly` | 上游已确认事实，只读复用 | 员工关系、企业主体、住宿单、价格快照、押金余额 |
| `objectPicker` | 从对象列表选择，不手填 | 主体、联系人、住客、房间、床位、价格快照 |
| `controlledSelection` | 从权威选项集选择 | 币种、周期、状态、原因、责任域、证据类型 |
| `userCurrentInput` | 用户本次必须输入 | 金额确认、入住/退住时间、人数、必要管理说明 |
| `optionalNote` | 可选补充说明，不作为事实主来源 | 备注、补充说明、特殊需求 |

## 少填规则

1. 来源、主体、企业、员工关系、房间、床位、价格快照、财务回执、证据状态一旦上游已确认，下游只读带出。
2. 房间、床位、主体、企业、联系人和住客只能用 `objectPicker`，不得用文本框。
3. 币种默认 `KGS`，只有价格快照、企业协议或财务规则要求时才允许切换。
4. 原因类字段必须先选受控原因，再允许填写 `optionalNote`。
5. 金额输入必须和币种、收付方向、金额阶段、业务对象同屏，不允许单独金额框。
6. 主按钮来自 `legalActions`，不得放入输入字段。
7. 当前页面只收集当前步骤需要的信息，不提前收集未来步骤字段。
8. 同一个事实只在归属域确认一次，后续页面只读复用或发起修正。

## 自由文本边界

允许自由文本的字段必须满足：

- 字段名以 `.optional` 结尾，或属于管理/审计必须说明字段。
- 页面已先提供受控类型、原因或责任域。
- 字数上限明确，默认 200 字；管理拍板和审计修正默认 500 字。
- 不作为状态、金额、责任域、证据、房间床位或主体的事实来源。
- 不进入搜索主标题，只能进入详情补充说明或审计备注。

禁止自由文本承担：

- 房间、床位、主体、企业、联系人、住客。
- 币种、收付方向、金额阶段。
- 房态、床态、证据类型、阻断原因。
- 取消、未到店、退住、结算、扣减、退款的主原因。
- 财务承接状态或财务确认结果。

## 最少输入页面策略

| 页面类型 | 用户最多应填 | 系统必须带出 |
| --- | --- | --- |
| 接入报价 | 入住日期、周期、人数、少量偏好 | 来源、诉求、主体候选、证据状态 |
| 房间床位选择 | 可选偏好或锁定备注 | 主体、可用房间床位、价格快照、风险 |
| 押金/收款承接 | 金额确认或财务备注 | 住宿单、主体、价格、币种、业务对象、证据 |
| 入住确认 | 实际入住时间、交付备注 | 主体、床位、财务回执、身份和交付证据 |
| 续住/换房 | 续住周期或换房受控原因 | 当前住宿、押金余额、目标资源、差额依据 |
| 退住结算 | 退住时间、检查/金额补充 | 住宿单、押金余额、检查、损耗证据 |
| 取消/未到店 | 受控原因和可选说明 | 预订、床位锁定、联系记录、已承接金额 |
| 恢复可经营 | 检查结果和可选说明 | 服务完成摘要、房态床态、检查证据 |

## 阻断与补交

当页面不可提交时，不让用户猜：

- 阻断原因显示来自 `blocked.reason`。
- 责任域显示来自 `responsibility.domain` 或 `handoff.next_role`。
- 可补交证据显示来自 `evidence.type` 和 `evidence.status`。
- 可继续动作来自 `legalActions`。
- 下一步来自 `handoffSummary`。

阻断页面不得只显示错误码、内部 key、旧中文状态或“失败”。

## 验收

不通过情况：

- `editableInputs` 包含系统可带出的来源、主体、房间、床位、财务回执或证据状态。
- 需要选择对象时出现文本框。
- 固定选项没有选项集。
- 备注字段成为唯一原因。
- 页面把“提交审核、确认入住、申请财务承接”等动作当作字段。
- 移动端为了省空间隐藏金额、币种、证据状态或下一步。
